1. Tổng quan kiến trúc

UniTrack là SDK analytics dạng core + provider:

  • Core (C++) — SQLite offline queue + exponential backoff retry. Mọi event qua đây trước khi flush mạng.
  • Auto-capture — Swift / Kotlin swizzler bắt tap + screen + network + crash. App không cần code track thủ công.
  • Provider fan-out — mỗi event sau khi vào core sẽ broadcast tới N provider đã register (Snowplow / Firebase / HTTP custom). Provider tự chuyển sang format của tracking platform.
App code (Swift / Kotlin / Dart)
     ↓
UniTrack singleton  ── auto-capture swizzler bắt event
     ↓
Core SQLite queue (offline-friendly, retry tự động)
     ↓
Fan-out tới N provider
     ├─→ Snowplow Provider     → POST collector
     ├─→ Firebase Provider     → logEvent()
     └─→ HTTP Provider (custom) → POST endpoint của bạn

1.1 Cấu hình bằng JSON local — không cần fetch portal

SDK đọc trackingConfig.json ở app bundle / assets ngay khi launch. App không cần gọi API config từ server — mọi setup (endpoint, batch size, provider toggle) đều khai báo file JSON. Đổi flavor → dùng deep-merge override.

2. iOS Setup SPM

2.1 Dependency

Xcode → File → Add Package Dependencies → URL:

https://github.com/sieuvitdet/unitrack-ios-package.git

  • UniTrackSnowplow — Snowplow provider (chỉ link nếu dùng Snowplow).

2.2 Config JSON

Add file trackingConfig.json vào project + Xcode target Build Phases → Copy Bundle Resources.

2.3 Bootstrap trong AppDelegate

Code tối thiểu để init SDK:

import UniTrack
import UniTrackSnowplow  // Chỉ cần nếu dùng Snowplow provider

func application(_ application: UIApplication,
                 didFinishLaunchingWithOptions launchOptions: ...) -> Bool {
    // 1. Load config JSON
    guard let url = Bundle.main.url(forResource: "trackingConfig", withExtension: "json"),
          let data = try? Data(contentsOf: url),
          let cfg = try? JSONSerialization.jsonObject(with: data) as? [String: Any]
    else { return true }

    // 2. Build UniTrack.Config từ cfg["sdk_config"]
    let sdkCfg = cfg["sdk_config"] as? [String: Any] ?? [:]
    var config = UniTrack.Config()
    config.batchSize       = sdkCfg["batchSize"]       as? Int  ?? 10
    config.flushIntervalMs = sdkCfg["flushIntervalMs"] as? Int  ?? 3000
    config.autoCapture     = sdkCfg["autoCapture"]     as? Bool ?? true
    config.trackScreens    = sdkCfg["trackScreens"]    as? Bool ?? true
    config.trackTaps       = sdkCfg["trackTaps"]       as? Bool ?? true

    UniTrack.initialize(apiKey: "YOUR_API_KEY", config: config)

    // 3. (Optional) Add Snowplow provider
    if let sp = cfg["snowplow"] as? [String: Any],
       (sp["enabled"] as? Bool) == true {
        let provider = SnowplowProvider(
            endpoint:       sp["endpoint"] as? String ?? "",
            appId:          sp["appId"] as? String ?? "app",
            igluVendor:     sp["iglu_vendor"] as? String,
            defaultVersion: sp["default_version"] as? String ?? "1-0-0"
        )
        UniTrack.addProvider(provider)
    }

    return true
}

Đề nghị tách phần load JSON + init vào 1 file riêng (vd AnalyticsBootstrap.swift) để AppDelegate gọn.

3.3 Bootstrap trong Application

class MyApp : Application() {
    override fun onCreate() {
        super.onCreate()

        // 1. Load config JSON từ assets
        val raw = assets.open("tracking_config.json").bufferedReader().use { it.readText() }
        val cfg = JSONObject(raw)
        val sdkCfg = cfg.optJSONObject("sdk_config") ?: JSONObject()

        // 2. Build UniTrackConfig
        val config = UniTrackConfig(
            batchSize       = sdkCfg.optInt("batchSize", 10),
            flushIntervalMs = sdkCfg.optInt("flushIntervalMs", 3000),
            autoCapture     = sdkCfg.optBoolean("autoCapture", true),
            trackScreens    = sdkCfg.optBoolean("trackScreens", true),
            trackTaps       = sdkCfg.optBoolean("trackTaps", true),
        )
        UniTrack.initialize(this, apiKey = "YOUR_API_KEY", config = config)

        // 3. (Optional) Add Snowplow provider
        val sp = cfg.optJSONObject("snowplow")
        if (sp?.optBoolean("enabled") == true) {
            val provider = SnowplowProvider(
                context        = this,
                endpoint       = sp.getString("endpoint"),
                appId          = sp.getString("appId"),
                igluVendor     = sp.optString("iglu_vendor"),
                defaultVersion = sp.optString("default_version", "1-0-0")
            )
            UniTrack.addProvider(provider)
        }
    }
}

4.1 Các trường chính

FieldÝ nghĩa
endpointCore HTTP queue URL. Rỗng → SDK chỉ fan-out qua provider (Snowplow / Firebase). Đặt URL để có ingest backup riêng.
pii_salt32-byte hex random, dùng cho SHA-256 hash PII fields. Sinh 1 lần, giữ identical 2 platform.
sdk_config.batchSizeSố event mỗi lần flush HTTP. Default 10.
sdk_config.flushIntervalMsInterval flush khi queue chưa đầy batch. Default 3000ms.
sdk_config.autoCaptureMaster toggle. False = SDK chỉ chạy event app gọi thủ công.
sdk_config.trackScreensTự bắt UIViewController appear / Activity resume.
sdk_config.trackTapsTự bắt button tap.
sdk_config.trackNetworkTự bắt URLSession / OkHttp request (cẩn thận PII trong URL).
snowplow.*Snowplow provider config. Để enabled: false nếu không dùng.
firebase.enabledTrue → SDK gọi FirebaseAnalytics.logEvent(...) qua reflection. Phải có Firebase SDK trong app.
tracing.allowlist_hostsInject traceparent W3C header vào outgoing request. Fail-closed: list rỗng = không inject.
flavors.<name>.*Deep-merge override. Build flavor = tên này → load merged config.
2 file JSON iOS + Android phải identical. Nên dùng symlink (UNIX) hoặc CI step copy 1 → 2.

5. Tracking events

SDK auto-bắt tap + screen + crash → app KHÔNG phải code thêm cho event chuẩn. App chỉ cần:

  • Đặt accessibility identifier / tag để event tap có element_key meaningful.
  • Đặt view controller title / Activity name để screen_view có name đẹp.
  • Gọi UniTrack.track(...) thủ công cho business event chưa có swizzler bắt.

5.1 Track event thủ công

iOS

UniTrack.track("purchase_completed", properties: [
    "order_id": orderId,
    "amount": 99000,
    "currency": "VND"
])

Android

UniTrack.track("purchase_completed", mapOf(
    "order_id" to orderId,
    "amount"   to 99000,
    "currency" to "VND"
))

track không gắn schema cụ thể — event name = key downstream filter. Phù hợp khi BE dùng schema-less store (vd Elasticsearch, BigQuery raw JSON).

6. Custom event với Iglu schema

Khác track() ở chỗ schema name được map ra Iglu URI ở Snowplow Provider. Dùng khi:

  • BE Snowplow yêu cầu event tuân theo Iglu schema đã register.
  • Cần stamp event_action field để phân biệt action trong cùng schema.
  • Cần kèm user_id hashed từ identify() cache.

6.1 API signature

// iOS
UniTrack.customTrack(
    _ eventName: String,
    action: String? = nil,
    data: [String: Any] = [:],
    includeUser: Bool = false
)

// Android
UniTrack.customTrack(
    eventName: String,
    action: String? = null,
    data: Map<String, Any?> = emptyMap(),
    includeUser: Boolean = false
)
ParamMô tả
eventNameIglu schema name (snake_case). Phải khớp schema đã register ở Iglu registry.
actionGiá trị field event_action trong payload. Nil → SDK dùng eventName.
dataField payload tự do.
includeUsertrue → kèm user_id (hashed) từ identify() cache.

6.2 Pattern 1: 1 schema = 1 action

iOS

UniTrack.customTrack("banner_clicked", data: [
    "banner_id": "home_top",
    "position": 0
])
// → schema: iglu:com.yourcompany.tracker/banner_clicked/jsonschema/1-0-0
// → event_action: "banner_clicked"

Android

UniTrack.customTrack("banner_clicked", data = mapOf(
    "banner_id" to "home_top",
    "position"  to 0
))

6.3 Pattern 2: 1 schema = nhiều action

Gom event domain cùng shape dưới 1 schema, phân biệt bằng action:

iOS

UniTrack.customTrack("payment_event", action: "payment_completed", data: [
    "order_id": orderId,
    "amount": 99000
], includeUser: true)

UniTrack.customTrack("payment_event", action: "payment_failed", data: [
    "order_id": orderId,
    "error_code": "INSUFFICIENT_BALANCE"
])
// → cả 2 chung schema: iglu:com.yourcompany.tracker/payment_event/jsonschema/1-0-0

Android

UniTrack.customTrack(
    eventName = "payment_event",
    action = "payment_completed",
    data = mapOf("order_id" to orderId, "amount" to 99000),
    includeUser = true
)
Iglu schema phải register trước ở Iglu registry. Snowplow Tracker silently drop event nếu schema không tồn tại. Schema dùng cho Pattern 2 phải có field event_action kiểu enum để accept mọi action.

7. Identify user

Gọi identify sau khi user login thành công. Sau đó mọi event có includeUser: true sẽ kèm user_id này.

7.1 Identify / Reset

iOS

// Login success
UniTrack.identify(userId: hashedUserId, traits: [
    "plan": "premium",
    "signup_date": signupDate
])

// Logout
UniTrack.reset()

Android

UniTrack.identify(userId = hashedUserId, traits = mapOf(
    "plan" to "premium"
))

UniTrack.reset()

7.2 PII hashing (SHA-256 + salt) — khuyến nghị

Nếu BE / data team yêu cầu KHÔNG nhận raw user_id / phone_number / email (rất phổ biến vì lý do GDPR / data residency) → bắt buộc hash trước khi truyền vào identify.

Công thức:

hashedValue = SHA-256(pii_salt + rawValue)

Salt lấy từ pii_salt trong trackingConfig.json. Cùng salt → cùng hash → BE dedup user.

iOS — helper SHA-256

import CryptoKit

func hashPII(_ raw: String, salt: String) -> String {
    let input = (salt + raw).data(using: .utf8)!
    let digest = SHA256.hash(data: input)
    return digest.map { String(format: "%02x", $0) }.joined()
}

// Sau khi login:
let hashedId = hashPII(rawUserId, salt: piiSalt)
UniTrack.identify(userId: hashedId)

Android — helper SHA-256

import java.security.MessageDigest

fun hashPII(raw: String, salt: String): String {
    val digest = MessageDigest.getInstance("SHA-256")
    val bytes = digest.digest((salt + raw).toByteArray(Charsets.UTF_8))
    return bytes.joinToString("") { "%02x".format(it) }
}

// Sau khi login:
val hashedId = hashPII(rawUserId, piiSalt)
UniTrack.identify(userId = hashedId)

8. Provider — Snowplow / Firebase / HTTP custom

Provider là adapter giữa UniTrack core và tracking platform cụ thể. App đăng ký N provider — mỗi event tự broadcast tới hết.

8.1 Snowplow Provider

Đã show ở Section 2.3 + 3.3. Provider tự đính kèm 3 entity:

  • user_context — userId + traits từ identify().
  • application_context — app version, device, network type.
  • core_action — session_id, event sequence.

8.2 Firebase Analytics Provider

SDK reflection-based — KHÔNG link Firebase symbol. App phải có firebase-analytics trong dependencies.

iOS

// Sau khi UniTrack.initialize
if cfg["firebase"] as? [String: Any]?["enabled"] as? Bool == true {
    UniTrack.attachFirebaseAdapter()
}

Android

UniTrack.attachFirebaseAdapter(this)

8.3 HTTP Custom Provider

Khai báo trong JSON http_providers[] để dump event sang Kibana / ELK / nội bộ:

"http_providers": [
    {
        "name": "internal_kibana",
        "url": "https://kibana.yourcompany.com/_bulk",
        "format": "ndjson",
        "headers": { "Authorization": "Bearer ${KIBANA_TOKEN}" },
        "event_filter": ["crash", "network_error"]
    }
]

SDK đọc list này lúc bootstrap, init HttpProvider cho từng entry, đăng ký vào fan-out. App KHÔNG cần code thêm.

9. Flutter add-to-app (cross-binary)

Nếu app native iOS / Android nhúng Flutter module → 2 binary cùng link UniTrack SDK. Mặc định mỗi binary tạo 1 singleton riêng → session_id khác nhau, user journey bị cắt khi user chuyển native ↔ Flutter screen.

SDK đã wire HostProxy auto-detect: Flutter plugin tự forward call qua singleton native. App KHÔNG cần code thêm.

9.1 Setup Flutter module

Bước 1: Add dependency

Trong pubspec.yaml:

dependencies:
  unitrack: ^1.3.1

Bước 2: Bật cờ skipVendor (chỉ Android)

Plugin Android mặc định vendor native binary. Nếu native host đã link unitrack qua Maven → duplicate class. Set flag để plugin skip vendor:

Trong android/gradle.properties của Flutter module:

unitrack.skipVendor=true

iOS: Không cần làm gì — Swift module isolation tự handle.

Bước 3: Init bình thường ở Dart side

import 'package:unitrack/unitrack.dart';

void main() async {
    WidgetsFlutterBinding.ensureInitialized();
    await UniTrack.instance.initialize(
        apiKey: 'utk_xxx',
        config: UniTrackConfig(autoCapture: true, trackTaps: true),
    );
    runApp(MyApp());
}

// Wrap MaterialApp với observer auto-capture
MaterialApp(
    navigatorObservers: [UniTrackRouteObserver()],
    builder: (ctx, child) => UniTrackTapObserver(child: child!),
    ...
);

// Track event thủ công ở Flutter screen
UniTrack.instance.track('my_event', properties: {...});
UniTrack.instance.customTrack('payment_event', action: 'completed', data: {...});

9.2 Verify HostProxy active

Cold start app, log expected:

// iOS Xcode console + Android logcat
[UniTrackPlugin] co-resident: skip Flutter init, piggyback native UniTrack singleton

Nếu thấy → Flutter event chung session_id với native. Nếu KHÔNG → plugin chạy standalone → 2 singleton song song.

9.3 Cách hoạt động (tóm tắt)

Plugin Swift dùng NSClassFromString("UniTrack.UniTrack") (iOS) hoặc Class.forName("com.unitrack.sdk.UniTrack") (Android) để detect native UniTrack class. Nếu thấy → mọi call (track, customTrack, setScreen...) forward qua ObjC runtime / Java reflection về singleton native. Plugin KHÔNG init module-local → zero duplicate SQLite, zero duplicate session_id.

Lưu ý: Khi app standalone (Flutter app thuần, không có native host) → plugin tự fallback init full SDK của riêng nó. Cùng 1 code Dart chạy được cả 2 mode.

10. RN React Native add-to-app (cross-binary)

Pattern giống Flutter: nếu app native embed RN bundle → 2 binary cùng link UniTrack SDK. SDK đã wire HostProxy auto-detect — mỗi call JS forward qua singleton native, không tạo singleton riêng.

10.1 Setup RN module

Bước 1: Add dependency

npm install unitrack-react-native
# hoặc
yarn add unitrack-react-native

Bước 2: Bật cờ skipVendor (chỉ Android)

Plugin Android RN mặc định kéo com.github.sieuvitdet:unitrack-sdk qua Maven. Nếu native host đã link cùng artifact → Gradle báo duplicate class. Set flag để plugin đổi sang compileOnly:

Trong android/gradle.properties của app RN:

unitrack.skipVendor=true

iOS: Không cần làm gì — Swift module isolation tự handle giống Flutter.

Bước 3: Init bình thường ở JS side

import UniTrack from 'unitrack-react-native';

await UniTrack.initialize('utk_xxx', {
    autoCapture: true,
    trackTaps: true,
});

// Track event thủ công ở component RN
UniTrack.track('my_event', { key: 'value' });

// Custom event với Iglu schema (parity Flutter customTrack)
UniTrack.customTrack('payment_event', {
    action: 'payment_completed',
    data:   { order_id: orderId, amount: 99000 },
    includeUser: true,
});

10.2 Verify HostProxy active

Cold start app, log expected:

// iOS Xcode console
[UniTrack/RN] co-resident: skip RN init, piggyback native singleton

// Android logcat (khi skipVendor=true + host supply UniTrack Maven)
[UniTrack] initialized (singleton native host)

Nếu thấy log co-resident iOS → JS event chung session_id với native. Nếu KHÔNG → RN chạy standalone → 2 singleton song song trong process.
