UniTrack Web SDK — Hướng dẫn tích hợp

Tự động thu thập screen view, click, network và session. Nhúng một file, gọi một hàm.

Bản demo chạy thật: showcase.html — mở DevTools › Network, lọc tp2 để xem event bắn đi ngay khi bạn click.

1. Lấy SDK

Hai cách. Giao SDK cho một đội khác tích hợp thì dùng npm — họ không phải xin file, không phải nhớ copy lại mỗi lần có bản mới.

Cách 1 — npm khuyến nghị

npm install unitrack-web

Copy file config mẫu kèm sẵn trong package ra thư mục tĩnh rồi sửa:

cp node_modules/unitrack-web/unitrack.config.example.json public/unitrack.config.json
import UniTrack from 'unitrack-web';

await UniTrack.initializeFromConfig('/unitrack.config.json');

Package có sẵn khai báo kiểu TypeScript, nên gợi ý code và bắt lỗi hoạt động ngay không cần cài thêm gì.

TrườngFileDùng cho
maindist/unitrack.cjs.jsCommonJS — require()
moduledist/unitrack.esm.jsESM — bundler tự chọn cái này
unpkgdist/unitrack.iife.jsNhúng thẳng thẻ script
typesdist/index.d.tsTypeScript

Cách 2 — copy file thủ công

Dự án không dùng bundler (HTML thuần, WordPress) thì lấy thẳng file IIFE:

<script src="/assets/js/unitrack.iife.js"></script>

File nặng 126 KB, nén gzip còn 33 KB. Cài qua npm rồi vẫn nhúng kiểu này được — file nằm ở node_modules/unitrack-web/dist/unitrack.iife.js.

Giao SDK cho đội khác thì npm hơn ở đâu: nâng cấp chỉ cần npm update unitrack-web thay vì gửi file mới rồi dặn nhau copy đúng chỗ; version ghi trong package-lock.json nên biết chính xác ai đang chạy bản nào; và khai báo TypeScript có sẵn.

2. Tích hợp trong ba bước

Bước 1 — Nhúng file

Đặt ngay trước thẻ đóng </head>, càng sớm càng tốt để không bỏ lỡ event đầu trang.

<script src="/assets/js/unitrack.iife.js"></script>

Bước 2 — Khởi tạo

<script>
// Tham số 1 là API key, tham số 2 là config.
UniTrack.initialize('YOUR_API_KEY', {
  endpoint: 'https://collector.example.com',
});

// Gắn nơi nhận dữ liệu.
UniTrack.addProvider(new UniTrack.HttpProvider({
  endpoint: 'https://collector.example.com',
  apiKey:   'YOUR_API_KEY',
}));
</script>

Xong. Từ giây này SDK tự bắt screen view, click, network request và vòng đời session — bạn không cần gọi gì thêm.

Tên hàm là initialize, không phải init. Và phải gọi addProvider() — thiếu bước này SDK vẫn chạy, vẫn in log ra Console, nhưng không có gì được gửi đi đâu cả.

Bước 3 — Gắn định danh khi user đăng nhập

// Sau khi đăng nhập thành công
UniTrack.identify('user-12345', {
  plan: 'premium',
});

// Khi đăng xuất — bắt buộc gọi, nếu không phiên sau vẫn mang danh tính cũ
UniTrack.reset();

Đừng truyền email, số điện thoại hay CMND vào identify(). Truyền ID nội bộ. Nếu buộc phải dùng dữ liệu nhạy cảm, bật piiSalt trong config để SDK tự băm SHA-256 trước khi gửi.

Gửi sang Snowplow thay vì HTTP

UniTrack.addProvider(new UniTrack.SnowplowProvider({
  endpoint:   'https://sp.example.com',
  appId:      'my-web-app',
  igluVendor: 'com.mycompany',
}));

Gắn được nhiều provider cùng lúc — dữ liệu fan-out song song sang từng nơi.

2b. Cách khuyến nghị — config bằng file JSON giống FPT Life

Cách ở mục 2 phải viết thông tin vào code. Nếu muốn mọi thứ nằm sẵn trong một file JSON — giống hệt trackingConfig.json mà FPT Life dùng trên iOS và Android — thì dùng cách này.

Khởi tạo bằng đúng một dòng:

<script src="/assets/js/unitrack.iife.js"></script>
<script>
  UniTrack.initializeFromConfig('/unitrack.config.json');

  // Chọn môi trường — lấy khối override trong "flavors"
  // UniTrack.initializeFromConfig('/unitrack.config.json', 'dev');
</script>

Không cần gọi addProvider(). SDK tự gắn provider theo file: snowplow.enabled bật thì gắn Snowplow, endpoint khác rỗng thì gắn HTTP. Đổi cấu hình chỉ sửa file JSON, không build lại.

Dùng chung một file cho cả web và mobile

Schema này giống hệt file iOS/Android đang chạy, giữ nguyên cả snake_case (sdk_config, iglu_vendor, allowlist_hosts). Cùng một file dùng được cho cả ba nền. Phần web không dùng (firebase, http_providers) thì SDK bỏ qua, không báo lỗi.

KhoáÝ nghĩa
apiKeyKhoá dự án, nằm trong file
endpointCore HTTP ingest. Rỗng thì chỉ gửi Snowplow
pii_saltỞ cấp gốc, không nằm trong sdk_config
sdk_config.logLeveldebug mới bật log; warn/error đều im lặng
snowplow.webĐè endpoint/appId riêng cho web, như ios/android bên native
snowplow.event_namesĐổi tên event khi lên wire
snowplow.drop_eventsChặn hẳn vài event không gửi
tracing.allowlist_hostsChỉ chèn traceparent cho host trong danh sách
flavorsOverride theo môi trường, deep-merge lên gốc

allowlist_hosts chỉ có tác dụng khi tracing.enabled là true. Đây là thứ ngăn traceparent rò sang bên thứ ba.

Với flavors, mảng bị thay nguyên cụm chứ không nối — khai allowlist_hosts trong flavor là bỏ hẳn danh sách gốc.

Khoá mobile có mà web chưa hỗ trợ

Dùng chung file với iOS/Android thì sẽ gặp vài khoá web bỏ qua. Để trong file không sao — SDK không báo lỗi, chỉ là không có tác dụng.

KhoáVì sao web bỏ qua
sdk_config.session_id_saltWeb chưa cài đặt. Mobile dùng để gắn tiền tố vào session_id (<tag8>-<uuid>) tách dữ liệu theo môi trường
snowplow.optionsCờ của Snowplow tracker gốc. Web tự viết provider nên không dùng
snowplow.hybrid_screen_viewChuyển sang schema ScreenView dựng sẵn của Snowplow mobile — web không có
snowplow.entitiesWeb luôn gắn user_context và application_context, chưa đọc bảng đổi tên này
snowplow.ios / snowplow.androidOverride của nền khác. Web đọc khối web
firebaseSDK riêng, web không nhúng
http_providersWeb gắn tay bằng addProvider()

3. Bắn event nghiệp vụ

UniTrack.track('add_to_cart', {
  product_id: 'SKU-991',
  price:      450000,
  quantity:   2,
});

Mỗi event tự động được gắn thêm session_id, session_index, screen và ts. Bạn không cần truyền tay.

4. Kiểu dữ liệu — mọi field đều là String quan trọng

Đây là điểm dễ gây bất ngờ nhất, nên nói rõ ngay từ đầu.

Payload gửi lên luôn có mọi giá trị ở dạng chuỗi, kể cả khi bạn truyền vào số hay boolean. SDK tự chuyển ở bước cuối trước khi gửi.

// Bạn viết thế này
UniTrack.track('add_to_cart', { price: 450000, in_stock: true });

// Thứ thực sự đi lên mạng
{ "price": "450000", "in_stock": "true", "session_index": "26", ... }

Lý do: cùng một field ở các nguồn phát khác nhau từng có kiểu khác nhau, khiến schema kiểm tra chặt ở phía nhận từ chối dữ liệu. Chuẩn hoá về một kiểu duy nhất giải quyết triệt để.

Bạn truyềnGửi lênGhi chú
26"26"Số nguyên
0.5"0.5"Giữ nguyên phần thập phân
true / false"true" / "false"false không bị loại bỏ
{a:1}'{"a":1}'JSON, không phải [object Object]
null / undefined— bị loại bỏKhông gửi field đó luôn

Khi phân tích dữ liệu, nhớ ép kiểu lại. Ví dụ trong SQL cần CAST(price AS INTEGER) trước khi tính tổng, nếu không sẽ nối chuỗi thay vì cộng số.

5. Event tự sinh

Không cần viết dòng nào, những event sau tự có:

EventKhi nàoField đáng chú ý
app_startLần tải trang đầu tiênnav_type, start_ms
screen_viewedVào một trang / route mớiscreen, title
screen_exitedRời trangdwell_ms, foreground_sec, reason
clickClick vào phần tử tương tácelement_key, tag, href
network_requestMỗi fetch / XHRurl, status_code, duration_ms
network_errorRequest ném lỗiurl, error
crashLỗi JS không bắt đượcmessage, stack
session_endedPhiên kết thúcended_session_id, session_duration_sec

Click được nhận diện thế nào

SDK tìm tên phần tử theo thứ tự ưu tiên sau. Muốn tên đẹp và ổn định, thêm data-track-id:

<button data-track-id="checkout_confirm">Thanh toán</button>
  1. data-track-id — bạn tự đặt, ổn định nhất
  2. id của phần tử
  3. aria-label
  4. Nội dung chữ, cắt còn 40 ký tự
  5. tag.class — phương án cuối

Click vào vùng trống không sinh event, nên bạn không bị nhiễu.

6. SPA — React, Vue, Next.js

SDK bắt được điều hướng của history.pushState, nên router phía client hoạt động sẵn. Chỉ cần init một lần ở entry point.

import UniTrack from 'unitrack-web';

// Config nằm hết trong file JSON — không hardcode gì vào code
await UniTrack.initializeFromConfig('/unitrack.config.json');

Next.js: đặt trong useEffect của layout gốc để chỉ chạy phía client — SDK cần window nên không chạy được lúc server render.

7. Config

endpoint là thứ duy nhất bạn gần như luôn phải đặt. Còn lại đều có mặc định hợp lý.

Tuỳ chọnMặc địnhÝ nghĩa

autoCapturetrueCông tắc tổng cho mọi thu thập tự động
trackScreenstrueScreen view và screen exit

trackLifecycletrueApp start, foreground, background

Cần chờ user đồng ý

UniTrack.initialize('YOUR_API_KEY', { endpoint: '...', requireConsent: true });

// Event bị giữ lại, chưa gửi đi. Khi user bấm "Đồng ý":
UniTrack.setConsent(true);

8. Tự kiểm tra khi nghi có lỗi

Làm lần lượt bốn bước, dừng ở bước nào hỏng thì đó là nguyên nhân.

SDK đã nạp chưa

Mở Console gõ UniTrack. Ra undefined nghĩa là thẻ script sai đường dẫn hoặc bị chặn.

Event có sinh ra không

Với verboseLogging: true, mỗi event in ra Console dạng [UniTrack] click {...}. Không thấy gì thì kiểm tra autoCapture và requireConsent.

Event có gửi đi không

DevTools › Network, lọc tp2. Phải thấy request POST mỗi vài giây. Nếu event in ra Console mà không có request, khả năng cao là endpoint sai hoặc bị CORS chặn.

Ép gửi ngay để thử

UniTrack.track('test_event', { hello: 'world' });
UniTrack.flush();   // không đợi batch, gửi luôn

10. Câu hỏi hay gặp

Có làm chậm trang không

Không đáng kể. SDK gom event vào bộ đệm và gửi nền, không chặn render.

Mất mạng thì sao

Event được lưu lại và gửi bù khi có mạng trở lại. Đóng tab giữa chừng cũng không mất, nhờ sendBeacon.

Có tự thu thập thông tin cá nhân không

Không. SDK không đọc nội dung người dùng nhập vào form — chỉ ghi nhận có tương tác với field nào. Định danh chỉ có khi bạn chủ động gọi identify().

Có cần banner cookie không

SDK dùng localStorage cho session chứ không dùng cookie theo dõi. Tuỳ quy định áp dụng cho bạn, có thể bật requireConsent để chờ đồng ý.

Tóm tắt

  1. Copy unitrack.iife.js vào thư mục tĩnh
  2. Nhúng thẻ script trong <head>
  3. Cách gọn nhất: tạo unitrack.config.json rồi gọi UniTrack.initializeFromConfig('/unitrack.config.json')
  4. Hoặc gọi tay: initialize(apiKey, { endpoint }) rồi addProvider(...)
  5. Gọi identify() lúc đăng nhập, reset() lúc đăng xuất
  6. Tắt verboseLogging trước khi lên production
  7. Nhớ ép kiểu khi phân tích — mọi field đều là String
