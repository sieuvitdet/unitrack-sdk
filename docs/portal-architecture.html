1. Tổng quan

UniTrack Portal là CMS quản lý cấu hình cho các SDK tracking mobile. Khi app mobile (iOS / Android / Flutter / React Native) khởi động, SDK gọi về Portal để lấy cấu hình: bật/tắt provider nào (Snowplow, Firebase, custom HTTP), bật W3C tracing, cấu hình auto-capture. Toàn bộ flow event tracking do SDK gửi thẳng tới các provider (Snowplow / Firebase / Kibana / backend nội bộ), Portal không lưu event của user.

3 chức năng chính của Portal:
  1. Authentication / phân quyền — user login, admin quản lý nhiều project
  2. Quản lý / tạo project — cấp API key cho từng app
  3. Quản lý cấu hình SDK theo project — sdk_config, snowplow, firebase, http_providers, W3C tracing

Tại sao stack tối giản này quan trọng cho hồ sơ hạ tầng:
  • Không cần build pipeline / CI — deploy = git pull && pm2 restart
  • Không cần Docker / Kubernetes — chạy thẳng trên 1 Linux VM
  • Không cần database tier riêng — SQLite file local đủ cho scope CMS
  • Không cần CDN — frontend là HTML tĩnh phục vụ qua nginx
  • App size: ~3 MB code + ~5 MB node_modules

5. Database (SQLite)

Portal dùng 1 file SQLite tại portal/data/events.db, truy cập qua Node 20 built-in module node:sqlite (không cần native binding). WAL mode để concurrent read.

Tables chính

TableMục đíchScope
users User login Portal (admin + project owner) Auth
sessions Cookie session login (KHÔNG phải session user-app) Auth
projects 1 row / project. Mỗi project có api_key riêng (Bearer token) Quản lý project
project_config JSON config của từng project: sdk_config, snowplow, firebase, tracing, http_providers Cấu hình SDK
events optional / debug Lưu event app gửi về (debug mode, không bắt buộc — app default gửi thẳng provider) Debug
app_sessions optional Phái sinh từ events, reconstruct session để debug Debug

Schema example — project_config

CREATE TABLE project_config (
  project_id     INTEGER PRIMARY KEY,
  endpoint       TEXT,                  -- UniTrack ingest endpoint
  sdk_config     TEXT,                  -- JSON: batchSize, flushIntervalMs, autoCapture flags
  snowplow       TEXT,                  -- JSON: {enabled, endpoint, appId, schemas}
  firebase       TEXT,                  -- JSON: {enabled, options:{...}}
  tracing        TEXT,                  -- JSON: {enabled, header_name, allowlist_hosts, sampled}
  http_providers TEXT,                  -- JSON array: [{id, endpoint, format, headers, ...}]
  version        INTEGER NOT NULL DEFAULT 1,
  updated_at     INTEGER NOT NULL
);

Kích thước thực tế

  • Hiện tại (7 project, vài MB config): file events.db ~54 MB
  • Sau 1 năm (15-20 project): ước tính ~100 MB nếu giữ debug mode
  • Sau 1 năm (chỉ config, không debug): <10 MB

7. SSE Realtime Config Stream

Khi operator sửa config ở Portal Web, SDK đang chạy trên app người dùng cần biết để pull config mới — không phải đợi app restart. Portal dùng Server-Sent Events (HTTP/1.1 streaming, không phải WebSocket) qua endpoint GET /config-stream.

Wire format

HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

event: hello
data: {"project_id":4}

event: config_changed
data: {"version":21}

: ping        ← heartbeat mỗi 25s, giữ connection sống

event: config_changed
data: {"version":22}

SDK đọc stream này, gặp event config_changed thì tự gọi lại GET /config với ETag — nếu version mới thì pull về và apply.

Lưu ý vận hành SSE:
  • nginx cần config proxy_buffering off + proxy_read_timeout 86400s cho path /config-stream
  • HTTP/2 hoạt động tốt hơn HTTP/1.1 (multiplexing — nhiều SSE concurrent không tốn TCP connection)
  • Heartbeat : ping mỗi 25 giây giữ connection qua proxy idle timeout

8. Background services trong process Node

Process event-tracking-portal spawn 2 thread con (qua setInterval, không phải worker thread):

ServiceTần suấtMục đíchBắt buộc?
Agent scheduler Tick mỗi 10 phút Cron daily 07:00 VN — chạy LLM analyze event của ngày hôm trước, gửi report Telegram Optional (off mặc định)
Telegram bot Long-poll 30s timeout Nhận lệnh từ Telegram chat (vd /report, /flows) → trả report Optional

Outbound network requirements (cho 2 service trên)

  • api.telegram.org:443 — bot polling + send message
  • LLM endpoint (vd api.openai.com:443 hoặc LLM nội bộ FPT)

Nếu trung tâm không dùng tính năng AI report Telegram, có thể tắt 2 service này và outbound firewall không cần whitelist 2 host trên.

10. Deploy quy trình

Lần đầu cài lên server ISC

# 1. Cài Node 20 + PM2 + nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install nodejs nginx
sudo npm install -g pm2

# 2. Clone code
git clone https://github.com/sieuvitdet/unitrack-sdk.git
cd unitrack-sdk/portal
npm install

# 3. Set env vars (qua systemd hoặc .env)
export PORT=4010
export HOST=127.0.0.1
export BASE_PATH=/event-tracking-mobile
export ADMIN_EMAIL=admin@fpt.vn
export ADMIN_PASS=<random>

# 4. Start với PM2
pm2 start server.js --name event-tracking-portal
pm2 save
pm2 startup    # auto-start khi reboot

# 5. Config nginx reverse proxy 443 → 4010 (xem section 11)
sudo certbot --nginx -d tracking.fpt.vn

Lần update sau

cd /root/event-tracking-portal
git pull
pm2 restart event-tracking-portal

Không cần build step. Không cần migration thủ công (SQLite migration tự chạy ở db.js lúc khởi động).

11. Nginx config mẫu

server {
    listen 443 ssl http2;
    server_name tracking.fpt.vn;

    ssl_certificate     /etc/letsencrypt/live/tracking.fpt.vn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tracking.fpt.vn/privkey.pem;

    # Default — proxy Node port 4010
    location / {
        proxy_pass http://127.0.0.1:4010;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SSE config stream — buffering OFF, timeout cao
    location /event-tracking-mobile/config-stream {
        proxy_pass http://127.0.0.1:4010;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 86400s;
    }

    # Rate limit ingest endpoint
    location /event-tracking-mobile/v1/events {
        limit_req zone=ingest burst=200 nodelay;
        proxy_pass http://127.0.0.1:4010;
    }
}

server {
    listen 80;
    server_name tracking.fpt.vn;
    return 301 https://$host$request_uri;
}

http {
    limit_req_zone $binary_remote_addr zone=ingest:10m rate=100r/s;
}

12. Security

AspectImplementation
Auth Web admin Email + password (bcrypt hash), cookie session HttpOnly + Secure flag
API auth (SDK) Per-project Bearer api_key (random 30+ char)
Secrets ở env ADMIN_PASS, LLM_API_KEY qua systemd env, không commit code
Header values với placeholder HttpProvider headers value ${ENV_*} resolve runtime — secret không lưu Portal DB
Rate limit ingest nginx limit_req 100r/s per IP
Firewall iptables default deny inbound, whitelist 22/80/443
OS hardening unattended-upgrades, fail2ban SSH, root login disabled

13. Câu hỏi cần xin từ ISC

  1. Cấp được Linux VM 2-4 vCPU / 2-4 GB RAM / 20-50 GB SSD chạy 24/7?
  2. Domain tracking.fpt.vn hoặc subdomain *.ftel.vn có sẵn cấp được không?
  3. TLS cert wildcard có sẵn hay phải Let's Encrypt?
  4. Backup storage chuẩn ISC: S3-compatible / NFS / rsync target?
  5. Outbound firewall: api.telegram.org + LLM endpoint có phải xin rule riêng?
  6. Monitoring dashboard chuẩn ISC (Grafana / Zabbix) wire vào thế nào?
