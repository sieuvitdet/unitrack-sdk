4.4 Custom track (event tự do, 1 dòng)

Khi cần track event chưa có helper sẵn — gọi FSDKTracking.customTrack(...) trực tiếp từ app code. SDK tự stamp session_id + user_id (nếu cần) trước khi gửi lên Snowplow.

API có ở 2 layer, FPT Life code nên dùng FSDKTracking.customTrack:

  • FSDKTracking.customTrack(...) — wrapper FPT Life, tự stamp thêm: app_id, platform. Khuyến nghị cho FPT Life để mọi custom event có shape giống helper camera/session sẵn.
  • UniTrack.customTrack(...) — API public SDK (iOS 0.3.50+ / Android 0.3.41+). Stamp base: event_action, session_id, user_id (nếu includeUser). Dùng khi không cần các field FPT-specific (vd app khác dùng SDK).

API signature

// iOS — UniTrack.swift
public static func customTrack(
    _ eventName: String,            // schema name = iglu:<vendor>/<eventName>/jsonschema/<ver>
    action: String? = nil,        // event_action field. nil → dùng eventName làm action
    data: [String: Any] = [:],   // field payload tự do
    includeUser: Bool = false     // true → stamp user_id từ UniTrack.identify() cache
)

// Android — UniTrack.kt
@JvmStatic @JvmOverloads
fun customTrack(
    eventName: String,
    action: String? = null,
    data: Map<String, Any?> = emptyMap(),
    includeUser: Boolean = false
)
ParamDefaultÝ nghĩa
eventName—Schema name — phải khớp với Iglu schema đã register ở BE. Snake_case.
actionnilGiá trị event_action field (filter downstream). Nil → SDK dùng eventName làm action.
data[:] / emptyMap()Field payload tự do. SDK tự thêm event_action + session_id.
includeUserfalseNếu true → stamp user_id từ UniTrack.identify() cache (FSDKTracking gọi identify với hashed PII rồi, nên giá trị stamp đã là hash).

Pattern 1: 1 schema = 1 action (event độc lập)

Mỗi event 1 schema riêng. Phù hợp cho event 1-off, payload khác biệt rõ rệt.

iOS

FSDKTracking.customTrack("banner_clicked", data: [
    "banner_id": "home_top_2026_06",
    "position": 0,
    "screen": "home"
])
// → schema: iglu:vn.fpt.ftel.snowplow/banner_clicked/jsonschema/1-0-0
// → event_action: "banner_clicked"

Android

FSDKTracking.customTrack("banner_clicked", data = mapOf(
    "banner_id" to "home_top_2026_06",
    "position"  to 0,
    "screen"    to "home"
))

Pattern 2: 1 schema = nhiều action (gom theo domain)

Gom nhiều event cùng domain dưới 1 schema chung, phân biệt bằng event_action. Phù hợp khi payload có shape giống nhau — BE đỡ phải register N schema cho N action.

iOS

// Tất cả dùng chung schema "payment_event"
FSDKTracking.customTrack("payment_event", action: "payment_completed", data: [
    "order_id": orderId,
    "amount": 99000,
    "method": "momo"
], includeUser: true)

FSDKTracking.customTrack("payment_event", action: "payment_failed", data: [
    "order_id": orderId,
    "error_code": "INSUFFICIENT_BALANCE"
], includeUser: true)

// → cả 2 dùng schema: iglu:vn.fpt.ftel.snowplow/payment_event/jsonschema/1-0-0
// → event_action: "payment_completed" hoặc "payment_failed"

Android

FSDKTracking.customTrack(
    eventName = "payment_event",
    action = "payment_completed",
    data = mapOf(
        "order_id" to orderId,
        "amount"   to 99000,
        "method"   to "momo"
    ),
    includeUser = true
)

FSDKTracking.customTrack(
    eventName = "payment_event",
    action = "payment_failed",
    data = mapOf(
        "order_id"   to orderId,
        "error_code" to "INSUFFICIENT_BALANCE"
    ),
    includeUser = true
)

So sánh 2 pattern

Pattern 1 (1-1)Pattern 2 (1-N)
Schema phải register1 cho mỗi event1 cho cả domain
Payload shapeTự do — khác nhau OKPhải tương đối giống (cùng schema validate)
BigQuery queryWHERE event_name = 'banner_clicked'WHERE event_name = 'payment_event' AND event_action = 'payment_completed'
Phù hợp khiEvent 1-off, payload đặc thùDomain có nhiều state (completed/failed/cancelled)

Field SDK tự stamp vào payload

FieldSourceTự stamp bởi
event_actionaction param hoặc eventName nếu nilUniTrack.customTrack
session_idUniTrack core sessionUniTrack.customTrack
user_idCached từ UniTrack.identify() (FSDKTracking đã hash SHA-256 trước khi identify)UniTrack.customTrack — chỉ khi includeUser: true
app_idFSDKTracking.appId (từ Snowplow config)FSDKTracking wrapper
platform"iOS" / "Android"FSDKTracking wrapper

App KHÔNG cần truyền 5 field trên trong data — wrapper + SDK auto stamp. Truyền vào sẽ bị overwrite.

Note: helper domain sẵn (vd sessionStarted, cameraStreamStarted) thêm cả login_session_id qua addLoginSession() — nhưng customTrack ad-hoc KHÔNG stamp field này vì nó là concept BE-specific (login session từ getUserInfo() API), không phù hợp cho event UI ad-hoc.

Nếu user chưa login (chưa gọi identify) → includeUser: true sẽ no-op, không stamp user_id.

BE Iglu schema phải register trước theo eventName. Snowplow Tracker silently drop event nếu schema chưa tồn tại.
Với Pattern 2: schema phải có field event_action kiểu enum để chấp nhận tất cả action có thể xảy ra.

5. Thêm helper dedicated vào FSDKTracking (optional)

Nếu 1 event được gọi nhiều nơi + có 5+ field bắt buộc → thêm helper dedicated để DEV không phải nhớ payload shape. Helper là wrapper 3-5 dòng quanh UniTrack.customTrack, expose typed params.

5.1 iOS

Thêm vào FSDKTracking+Events.swift:

static func paymentCompleted(orderId: String,
                              amount: Int,
                              method: String) {
    UniTrack.customTrack("payment_event",
                          action: "payment_completed",
                          data: [
                              "order_id": orderId,
                              "amount":   amount,
                              "method":   method,
                          ],
                          includeUser: true)
}

5.2 Android

Thêm vào FSDKTrackingEvents.kt:

fun paymentCompleted(orderId: String, amount: Int, method: String) {
    UniTrack.customTrack(
        eventName = "payment_event",
        action = "payment_completed",
        data = mapOf(
            "order_id" to orderId,
            "amount"   to amount,
            "method"   to method,
        ),
        includeUser = true
    )
}

Expose qua facade FSDKTracking.kt:

@JvmStatic
fun paymentCompleted(orderId: String, amount: Int, method: String) =
    FSDKTrackingEvents.paymentCompleted(orderId, amount, method)
Khi nào cần helper dedicated: event xài 5+ nơi, có 5+ field bắt buộc, hoặc có logic build payload phức tạp (nested object, conditional field). Nếu chỉ 1-2 lần dùng đơn giản → gọi thẳng customTrack, không cần wrapper.
BE Iglu schema cho event mới phải register trước. Snowplow Tracker sẽ silently drop event nếu schema chưa tồn tại.

6. Identify user (JWT + PII hash)

6.1 Auto identify từ Flutter access token

FSDKTracking đã wire vào subscribe .syncCheckExistingToken của Flutter bridge. Login → token có → parse JWT → identify. Logout → token nil → reset user_context.

iOS — AppEngine.swift

self.subscribe(action: .syncCheckExistingToken) { (res: FlutterLoginResponse) in
    let accessToken = res.dataSync.accessToken
    if let token = accessToken {
        AppAuthFPTID.shared.setAuthState(.init(accessToken: token))
    }
    FSDKTracking.applyAuthFromToken(accessToken)
}

6.2 Identify thủ công (nếu cần)

// iOS
FSDKTracking.identify(userId: phone, phoneNumber: phone)

// Android
FSDKTracking.identify(userId = phone, phoneNumber = phone)

6.3 Logout

FSDKTracking.clearIdentityAndReset()    // reset identity + UniTrack session + Snowplow user

6.4 PII hashing (SHA-256 + salt)

3 field bị hash trước outbound: user_id, phone_number, user_name. CSOC chặn raw phone_number trong payload.

Công thức: sha256_hex(pii_salt + raw_value). Cùng salt → cùng hash → BE dedup được.

Test vector cho data team

7. Cross-binary — Flutter trong app native

FPT Life là native iOS + Android nhúng Flutter module add-to-app (Flutter chạy trong cùng process với native, không phải process riêng). 2 binary cùng link UniTrack SDK → 2 singleton riêng → session_id khác nhau nếu không đồng bộ.

SDK đã wire HostProxy pattern: Flutter plugin detect native UniTrack rồi forward mọi call sang singleton native. Đội Flutter chỉ cần làm 3 việc, KHÔNG cần code thêm.

7.1 Vấn đề: 2 singleton, 2 session_id

Native process
┌─────────────────────────────────────────────────────┐
│  Native code (Swift / Kotlin)                       │
│     ↓                                                │
│  UniTrack singleton #1     session_id = ABC-123     │  ← Native event stamp ABC-123
│     ↓                                                │
│  Snowplow Provider #1      app_id = 505             │
│                                                      │
│  ─────────────────────                               │
│                                                      │
│  Flutter module (Dart)                               │
│     ↓                                                │
│  unitrack plugin (Flutter)                          │
│     ↓                                                │
│  UniTrack singleton #2     session_id = XYZ-789     │  ← Flutter event stamp XYZ-789 (KHÁC)
│     ↓                                                │
│  Snowplow Provider #2      app_id = 505 (init lại)  │  ← collector thấy 2 device
└─────────────────────────────────────────────────────┘

Hậu quả: data team thấy 1 user → 2 session_id song song, journey bị cắt khi user chuyển từ màn native → màn Flutter.

7.2 Cách giải quyết: HostProxy auto-detect

UniTrack Flutter plugin tự check class UniTrack.UniTrack tồn tại trong runtime qua NSClassFromString (iOS) / Class.forName (Android). Nếu có → biết là native đã link SDK → forward mọi call qua native singleton thay vì init singleton riêng.

Sau khi HostProxy active
┌─────────────────────────────────────────────────────┐
│  Native code                                         │
│     ↓                                                │
│  UniTrack singleton (DUY NHẤT)   session_id = ABC   │
│     ↑                                                │
│  HostProxy forward          ←── Flutter plugin call  │
│                                                      │
│  Snowplow Provider (DUY NHẤT)                        │
└─────────────────────────────────────────────────────┘

Mọi event Flutter fire (vd UniTrack.instance.track("camera_stream_started", ...) ở Dart) đều stamp session_id = ABC giống native → journey liên tục.

7.3 Hướng dẫn cho đội Flutter FPT Life

3 bước, không cần code thêm:

Bước 1: Add dependency Flutter

Trong pubspec.yaml của Flutter module:

dependencies:
  unitrack: ^1.3.0

Bước 2: Bật cờ skipVendor (chỉ Android)

Android plugin Flutter mặc định vendor native binary libunitrack_jni.so kèm. Vì host native FPT Life đã link unitrack-sdk:unitrack từ Maven, kéo plugin sẽ gây duplicate class error. Set 1 flag là plugin skip vendor:

Trong file android/gradle.properties của Flutter module:

unitrack.skipVendor=true

iOS: KHÔNG cần làm gì — Swift module isolation tự handle, không có duplicate symbol.

Bước 3: Init bình thường ở Dart side

Code Dart KHÔNG cần phân biệt co-resident hay standalone — plugin tự gate:

// main.dart
import 'package:unitrack/unitrack.dart';

void main() async {
    WidgetsFlutterBinding.ensureInitialized();
    await UniTrack.instance.initialize(
        apiKey: 'utk_xxx',
        config: UniTrackConfig(...),
    );
    // → Plugin detect native UniTrack class → init() no-op, forward setUser/track/...
    //   sang native singleton. Tất cả event stamp session_id của native.
    runApp(MyApp());
}

// ViewController/Screen Flutter — track event như standalone app
UniTrack.instance.track('camera_stream_started', properties: {
    'camera_serial': serial,
    'channel': 0,
});
// → Event đi qua HostProxy → native singleton → cùng session_id với event từ native side

7.4 Verify HostProxy đã active

Cold start app, tìm log:

// iOS — Xcode console
[UniTrackPlugin] co-resident detected — forwarding tới native singleton

// Android — logcat
[UniTrackPlugin] co-resident detected — forwarding tới native singleton

Nếu thấy log đó → mọi call Dart đã proxy sang native. Nếu KHÔNG thấy → plugin đang chạy standalone mode → 2 singleton song song.

7.6 Use case thực tế

User flow điển hình ở FPT Life:

  1. Native Login screen → FSDKTracking.applyAuthFromToken(jwt) → identify session bắt đầu.
  2. Native Home → tap "Camera live" → fire camera_stream_started (native).
  3. User nhấn icon → mở Flutter route (vd Settings) → Flutter screen fire screen_viewed (Flutter qua plugin).
  4. Snowplow collector: tất cả event trên có cùng session_id + cùng user_id → journey 4 step join được trên BigQuery.
