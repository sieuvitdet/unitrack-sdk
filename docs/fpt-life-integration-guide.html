2.2 Config JSON

Add file tracking_config.json vào app/src/main/assets/. Android pick từ assets tự động.

2.3 Bootstrap trong Application

Class Application của FPT Life Android là FLifeApp (đã đăng ký sẵn trong AndroidManifest). Gọi FSDKTracking.bootstrap trong onCreate:

import com.fpt.tracker.fsdk.FSDKTracking
import com.unitrack.sdk.UniTrack

class FLifeApp : Application() {
    override fun onCreate() {
        super.onCreate()

        FSDKTracking.bootstrap(
            app    = this,
            flavor = BuildConfig.FCAM_ENV,
        ) {
            FSDKTracking.sessionStarted()
            checkNotificationPermission()
        }

        // Wire foreground/background lifecycle để session rotate đúng
        UniTrack.addLifecycleListener { toForeground ->
            if (toForeground) {
                FSDKTracking.sessionStarted()
            } else {
                FSDKTracking.sessionEnded(reason = "backgrounded")
                UniTrack.flush()
            }
        }
    }
}
Field BuildConfig.FCAM_ENV = build flavor hiện tại (vd "dev", "beta", "uat") — dùng để chọn override trong block flavors của tracking_config.json.

4. Tracking events

Mọi event đi qua FSDKTracking — API identical iOS + Android. 3 nguồn event:

  • Auto-capture — SDK tự bắt screen + tap. App không gọi gì.
  • Pre-built helpers — 18+ hàm sẵn cho session + camera.
  • Custom track — event tự đặt, payload tự do.

4.1 Session lifecycle

HelperKhi nào gọi
sessionStarted(entrySource:)App foreground / cold start
sessionEnded(reason:)App background / kill

4.2 Auto-capture (screen + tap)

App KHÔNG gọi helper nào — SDK tự bắt theo cờ trong sdk_config của trackingConfig.json. Tên event mặc định lấy từ JSON, đổi được mà không cần rebuild.

Event nameTriggerBật/tắt
screen_viewed iOS: UIViewController viewDidAppear. Android: Activity onResume / Fragment onViewCreated. sdk_config.trackScreens + screen_start_event
screen_exited iOS: viewDidDisappear. Android: onPause / Fragment onDestroyView. Kèm duration_ms = thời gian dwell. sdk_config.trackScreens + screen_end_event
screen_load_completed Bắn cùng lúc screen_viewed với field load_ms = thời gian từ viewDidLoad / Activity onCreate đến lúc render xong. sdk_config.trackScreens + screen_load_event
click iOS: UITapGestureRecognizer / UIControl. Android: View.OnClickListener. Resolve element_key theo thứ tự: accessibilityIdentifier > tag > classname.method. sdk_config.trackTaps
Tên screen tự bắt: iOS lấy UIViewController.title; nếu rỗng → fallback class name. Android lấy Activity label / Fragment tag; nếu không có → fallback class name. App muốn override → đặt viewController.title / activity.title trước khi screen hiển thị.
Tắt trackScreens/trackTaps = bỏ hẳn 3 event screen + click trên CẢ pipeline (UniTrack core + Snowplow fan-out). Chỉ tắt khi BE muốn FPT Life tự gửi screen qua helper riêng (vd UniTrack.setScreen thủ công).

4.5 Custom track — event không có helper sẵn

Khi cần track event chưa có trong danh sách helper: gọi FSDKTracking.customTrack(...) 1 dòng. SDK lo phần stamp session_id / event_action / user_id.

API signature

// iOS
FSDKTracking.customTrack(
    _ eventName: String,
    action: String? = nil,
    data: [String: Any] = [:],
    includeUser: Bool = false
)

// Android
FSDKTracking.customTrack(
    eventName: String,
    action: String? = null,
    data: Map<String, Any?> = emptyMap(),
    includeUser: Boolean = false
)
ParamMô tả
eventNameSchema name (snake_case). Phải khớp Iglu schema đã register BE.
actionGiá trị event_action field. Nil → SDK dùng eventName.
dataField payload tự do.
includeUsertrue → kèm user_id (hashed) từ identify() cache.

Pattern 1: 1 schema = 1 action

Mỗi event 1 schema riêng. Phù hợp cho event 1-off, payload khác biệt.

iOS

FSDKTracking.customTrack("banner_clicked", data: [
    "banner_id": "home_top_2026_06",
    "position": 0,
    "screen": "home"
])
// → schema: iglu:vn.fpt.ftel.snowplow/banner_clicked/jsonschema/1-0-0
// → event_action: "banner_clicked"

Android

FSDKTracking.customTrack("banner_clicked", data = mapOf(
    "banner_id" to "home_top_2026_06",
    "position"  to 0,
    "screen"    to "home"
))

Pattern 2: 1 schema = nhiều action

Gom nhiều event cùng domain dưới 1 schema chung, phân biệt bằng event_action. Phù hợp khi payload shape giống nhau — BE chỉ register 1 schema cho N action.

iOS

FSDKTracking.customTrack("payment_event", action: "payment_completed", data: [
    "order_id": orderId,
    "amount": 99000,
    "method": "momo"
], includeUser: true)

FSDKTracking.customTrack("payment_event", action: "payment_failed", data: [
    "order_id": orderId,
    "error_code": "INSUFFICIENT_BALANCE"
], includeUser: true)

// → cùng schema: iglu:vn.fpt.ftel.snowplow/payment_event/jsonschema/1-0-0
// → event_action: "payment_completed" hoặc "payment_failed"

Android

FSDKTracking.customTrack(
    eventName = "payment_event",
    action = "payment_completed",
    data = mapOf(
        "order_id" to orderId,
        "amount"   to 99000,
        "method"   to "momo"
    ),
    includeUser = true
)

FSDKTracking.customTrack(
    eventName = "payment_event",
    action = "payment_failed",
    data = mapOf(
        "order_id"   to orderId,
        "error_code" to "INSUFFICIENT_BALANCE"
    ),
    includeUser = true
)

So sánh 2 pattern

Pattern 1 (1-1)Pattern 2 (1-N)
Schema phải register1 cho mỗi event1 cho cả domain
Payload shapeTự do — khác nhau OKPhải tương đối giống (cùng schema validate)
BigQuery queryWHERE event_name = 'banner_clicked'WHERE event_name = 'payment_event' AND event_action = 'payment_completed'
Phù hợp khiEvent 1-off, payload đặc thùDomain có nhiều state (completed/failed/cancelled)
BE Iglu schema phải register trước theo eventName. Snowplow Tracker silently drop event nếu schema chưa tồn tại.
Với Pattern 2: schema phải có field event_action kiểu enum để chấp nhận tất cả action có thể xảy ra.

4.6 Thêm helper dedicated (optional)

Khi 1 event được gọi nhiều nơi + có 5+ field bắt buộc → thêm helper dedicated để app code không phải nhớ payload shape. Wrapper 3-5 dòng quanh customTrack:

iOS — Thêm vào FSDKTracking+Events.swift

static func paymentCompleted(orderId: String,
                              amount: Int,
                              method: String) {
    FSDKTracking.customTrack("payment_event",
                          action: "payment_completed",
                          data: ["order_id": orderId, "amount": amount, "method": method],
                          includeUser: true)
}

Android — Thêm vào FSDKTrackingEvents.kt + expose qua FSDKTracking.kt

fun paymentCompleted(orderId: String, amount: Int, method: String) {
    FSDKTracking.customTrack(
        eventName = "payment_event",
        action = "payment_completed",
        data = mapOf("order_id" to orderId, "amount" to amount, "method" to method),
        includeUser = true
    )
}
Khi nào cần helper dedicated: event gọi 5+ nơi, có 5+ field bắt buộc, hoặc build payload phức tạp (nested object, conditional field). Đơn giản → gọi thẳng customTrack.

5. Identify user (JWT + PII hash)

5.1 Auto identify từ Flutter access token

FSDKTracking đã wire vào subscribe .syncCheckExistingToken của Flutter bridge. Login → token có → parse JWT → identify. Logout → token nil → reset user_context.

iOS — AppEngine.swift

self.subscribe(action: .syncCheckExistingToken) { (res: FlutterLoginResponse) in
    let accessToken = res.dataSync.accessToken
    if let token = accessToken {
        AppAuthFPTID.shared.setAuthState(.init(accessToken: token))
    }
    FSDKTracking.applyAuthFromToken(accessToken)
}

5.2 Identify thủ công (nếu cần)

// iOS
FSDKTracking.identify(userId: phone, phoneNumber: phone)

// Android
FSDKTracking.identify(userId = phone, phoneNumber = phone)

5.3 Logout

FSDKTracking.clearIdentityAndReset()    // reset identity + session + Snowplow user

5.4 PII hashing (SHA-256 + salt)

3 field bị hash trước outbound: user_id, phone_number, user_name. CSOC chặn raw phone_number trong payload.

Công thức: sha256_hex(pii_salt + raw_value). Cùng salt → cùng hash → BE dedup được.
