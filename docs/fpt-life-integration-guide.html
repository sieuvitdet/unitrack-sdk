1. Kiến trúc tổng quan

UniTrack là analytics SDK đa nền tảng, share C++ core. FPT Life dùng wrapper FSDKTracking (cùng tên cả iOS + Android) để abstract toàn bộ tracking domain — DEV gọi FSDKTracking.streamStarted(...), không trực tiếp dùng UniTrack API.

┌──── FPT Life app ─────────────────────────────┐ │ │ │ App code (UIKit / Activity / Fragment) │ │ │ │ │ ▼ │ │ FSDKTracking.swift / .kt (domain wrapper) │ │ │ │ │ ▼ │ │ UniTrack SDK (cross-platform) │ │ ├─ SnowplowProvider → ftracking.fpt.vn │ │ ├─ FirebaseAdapter → Firebase Analytics │ │ ├─ Core HTTP queue → ingest endpoint │ │ └─ SQLite offline → tự queue + retry │ │ │ └─────────────────────────────────────────────────┘
Convention: App KHÔNG gọi UniTrack.track(...) trực tiếp. Mọi event đi qua FSDKTracking để giữ event_name + schema chuẩn FPT Life.

2.3 Bootstrap trong AppDelegate

import UniTrack

func application(_ application: UIApplication,
                 didFinishLaunchingWithOptions launchOptions: ...) -> Bool {
    FSDKTracking.bootstrap {
        FSDKTracking.sessionStarted()
        // Optional: kiểm tra notification permission
        self.checkNotificationPermission()
    }
    // UNUserNotificationCenter delegate wrap để auto-capture notification clicks
    let center = UNUserNotificationCenter.current()
    center.delegate = UniTrackNotifications.wrap(center.delegate)
    return true
}

func applicationDidEnterBackground(_ application: UIApplication) {
    FSDKTracking.sessionEnded(reason: "backgrounded")
    UniTrack.flush()
}

func applicationWillEnterForeground(_ application: UIApplication) {
    FSDKTracking.sessionStarted()
}

4.3 Tránh duplicate event giữa UniTrack + Snowplow autotracking

UniTrack và Snowplow SDK có những lớp swizzler chạy độc lập. Nếu bật cùng lúc các cặp cờ dưới đây, mỗi screen / lifecycle sẽ bắn ra 2 event song song với event_name khác nhau — BE phải dedupe phía downstream:

UniTrack flagSnowplow flag (trong snowplow.options)Hậu quả nếu bật cả hai
sdk_config.trackScreens = true screenViewAutotracking = true Mỗi UIViewController appear bắn 2 event:
screen_viewed (UniTrack, screen_name strip module prefix) + screen_view (Snowplow, raw class name "MyApp.HomeVC"). Tránh: giữ screenViewAutotracking = false (mặc định của SDK).
FSDKTracking.sessionStarted() / sessionEnded() manual ở AppDelegate lifecycleAutotracking = true App foreground/background bắn 2 event:
session_started / session_ended (FSDKTracking manual) + application_foreground / application_background (Snowplow). Khác event_name nên không phải duplicate cứng, nhưng cùng nhịp lifecycle gây nhiễu phân tích. Tránh: giữ lifecycleAutotracking = false khi đã wire FSDKTracking.sessionStarted/Ended.
sdk_config.trackScreens = true DEV tự gọi UniTrack.setScreen(...) trong viewDidAppear UniTrack swizzler tự bắn screen + DEV bắn thủ công → 2 screen_viewed. SDK có manual arbitration (window 200ms) sẽ tự suppress auto khi DEV manual track, nhưng chỉ có hiệu lực trên iOS từ 0.3.36. Tránh: chọn 1 trong 2 — auto swizzler HOẶC manual setScreen, không trộn.
Config mặc định của FPT Life hiện tại an toàn: trackScreens = true + screenViewAutotracking không khai báo (default = false) + lifecycleAutotracking = false → 0 duplicate. Khi update JSON, đừng bật screenViewAutotracking hay lifecycleAutotracking nếu chưa rõ hậu quả.

4.4 Override theo flavor (dev / beta / uat / prod)

Base config trong file JSON là config prod. Khi app chạy build khác prod, SDK đọc thêm block flavors.<currentFlavor> và deep-merge override vào base (đệ quy không giới hạn cấp). Array trong override thay thế hoàn toàn array base, không concat. Nhờ deep merge, anh có thể override tới mọi cấp con: flavors.beta.snowplow.ios.endpoint chỉ thay 1 field này mà snowplow.options.*, snowplow.event_names.*, snowplow.android.*... vẫn giữ giá trị base.

Flavor mapping giữa app code và JSON key

PlatformSourceGiá trị flavor đẩy vào SDK
iOSEnvManager.shared.env.rawValue (từ APP_ENV Info.plist)dev / beta / uat / prod
AndroidBuildConfig.FCAM_ENV (build-logic convention)beta / prod

Quy tắc merge

Loại fieldHành vi
Scalar (string/number/bool) ở bất kỳ cấp nàooverride scalar replace base scalar
Nested object (vd sdk_config, tracing, snowplow, snowplow.ios, snowplow.options)deep merge đệ quy — chỉ key có trong override mới thay, key khác giữ nguyên base
Array (vd allowlist_hosts, http_providers)thay thế hoàn toàn, KHÔNG concat. Muốn giữ host base thì copy lại trong override.
Flavor không có trong block flavorsSDK dùng base config y nguyên + log flavor=X không có override, dùng base config

Ví dụ effective config khi build beta

// 1. SDK behaviour
// base.sdk_config.logLevel = "warn"
// flavors.beta.sdk_config.logLevel = "debug"
// → effective sdk_config.logLevel = "debug"
// → effective sdk_config.batchSize = 10 (giữ base vì beta không override)

// 2. Snowplow collector — override sâu tới snowplow.ios.endpoint
// base.snowplow.endpoint = "https://ftracking.fpt.vn"
// base.snowplow.appId   = "505"
// base.snowplow.options.base64Encoding = true
// flavors.beta.snowplow.endpoint   = "https://ftracking-beta.fpt.vn"
// flavors.beta.snowplow.appId      = "505-beta"
// flavors.beta.snowplow.ios.endpoint = "https://ftracking-beta.fpt.vn"
// flavors.beta.snowplow.ios.appId    = "505-beta"
// → effective snowplow.endpoint = "https://ftracking-beta.fpt.vn"
// → effective snowplow.ios.endpoint = "https://ftracking-beta.fpt.vn"
// → effective snowplow.options.base64Encoding = true   (giữ base vì beta không nhắc)
// → effective snowplow.event_names.* = base values     (giữ base hoàn toàn)

// 3. Tracing — array replace hoàn toàn
// base.tracing.allowlist_hosts        = ["api-fptlife.fcam.vn", ...]
// flavors.beta.tracing.allowlist_hosts = ["api-fptlife-beta.fcam.vn", ...]
// → effective allowlist_hosts = ["api-fptlife-beta.fcam.vn", ...]   (KHÔNG concat)

// 4. Tắt Snowplow ở dev chỉ với 1 dòng:
// flavors.dev.snowplow.enabled = false  → dev không gửi event lên collector

6. Tự định nghĩa custom event mới

Nếu helper sẵn không khớp use case (vd track button "Đăng ký gói Giga"), 2 cách:

6.1 Cách 1 (Recommended) — Thêm helper vào FSDKTracking

Pattern: tạo thêm method giống các method có sẵn → gọi snowplow?.trackingClickEvent(...) với event name + data.

iOS Swift — thêm vào FSDKTracking.swift

// MARK: - Subscription
static func packageRegistered(packageId: String,
                              source: String,
                              priceVnd: Int? = nil) {
    var data = baseData(.package_registered, includeUser: true)
    data["package_id"] = packageId
    data["source"]     = source
    addOptional(&data, ["price_vnd": priceVnd])
    snowplow?.trackingClickEvent(
        elementKey: FSDKEvent.package_registered.rawValue,
        data: data
    )
}

Cập nhật FSDKEvent.swift:

case package_registered = "package_registered"

Android Kotlin — thêm vào FSDKTracking.kt

fun packageRegistered(
    packageId: String,
    source: String,
    priceVnd: Int? = null
) {
    val data = baseData(FSDKEvent.PACKAGE_REGISTERED, includeUser = true)
        .toMutableMap()
    data["package_id"] = packageId
    data["source"]     = source
    priceVnd?.let { data["price_vnd"] = it }
    snowplow?.trackingClickEvent(
        elementKey = FSDKEvent.PACKAGE_REGISTERED.value,
        data = data
    )
}

Cập nhật FSDKEvent.kt:

PACKAGE_REGISTERED("package_registered"),

7.4 PII hashing (SHA-256 + salt) — bắt buộc cho user_id / phone_number / user_name

CSOC chặn payload chứa số điện thoại / username raw. Vì FPT Life dùng số điện thoại làm user_id, SDK phải hash trước khi attach vào outbound event payload. Hash dùng SHA-256 với salt cố định trong trackingConfig.json để chống rainbow-table / brute-force trên không gian phone Việt Nam (~109 combination).

Công thức hash

hash = sha256_hex( pii_salt || raw_value )    // concat string, lowercase 64-char hex output

Salt 32-byte (64 hex chars) đọc từ field pii_salt trong trackingConfig.json / tracking_config.json. Cùng salt → cùng hash deterministic → BE vẫn dedup được theo hash.

Cache 2 tầng

LayerStorageLifecycle
In-memoryDictionary trong PIIHashProcess — cold start mất
PersistentiOS UserDefaults · Android SharedPreferences (prefs name FSDKTrackingPIIHash)Reset khi logout (qua clearCachedIdentity() iOS / clearIdentity() Android)

Cache key gồm prefix 8 hex char đầu của sha256(salt) → đổi salt = key namespace đổi → cache cũ tự miss, không cần manual invalidate.

Chỗ áp dụng hash

Call siteField bị hash
FSDKTracking.identify(userId:phoneNumber:)userId, phoneNumber, user_name (= username slot)
FSDKTracking.applyAuthFromToken(_:) (iOS)Auto chạy khi Flutter báo accessToken; parse JWT → identify với phone hashed
FSDKTracking.restoreCachedIdentity() (iOS)userId, phoneNumber, user_name (cold start re-attach)
baseData(includeUser: true) (iOS) · outboundUserId() (Android)user_id trong mọi event payload (session_started, camera_stream_*, error, ...)
snowplow?.setUser(uid, traits)user_id + user_context entity attached vào mọi event

Output ví dụ

// trackingConfig.json
"pii_salt": "fe0430c4b75ff6ba73552117691ca0aba862a1633e5db6b0c1c8fa6b35203886"

// raw user input
phone_number = "0816361617"

// hash result (đã verify với openssl)
sha256(salt + phone) = "4a396957c9774848c80f1b5911f1d26e291c6a49a69c39da993e31730ff9b91f"
Đổi salt = mọi user phải re-hash. Cache cũ tự miss + hash mới khác hash cũ → BE phải bắt đầu join lại theo hash mới. Đừng đổi salt nếu chưa thông báo cho data team.
Không reversible (về lý thuyết): SHA-256 là one-way. Có salt 256-bit → brute-force public không khả thi nữa (attacker không build rainbow table sẵn vì không biết salt). Để link hash với real user, BE phải tự hash số điện thoại từ DB nội bộ (cùng salt) rồi join.

Hand-off cho đội Data

Khi bàn giao tracking flow cho data engineer / analyst, cung cấp 4 thông tin:

#ItemGiá trị / nơi lấy
1 Salt value — secret, gửi qua kênh nội bộ (Slack DM / 1Password, KHÔNG email / chat group) Field pii_salt trong trackingConfig.json
2 Công thức hash — để BE/data team replicate được khi cần join phone DB nội bộ sha256_hex(salt + raw_phone), UTF-8, lowercase hex, no separator giữa salt và raw
3 Test vector — để team self-verify implementation raw "0816361617" với salt fe04…3886 → 4a396957c9774848c80f1b5911f1d26e291c6a49a69c39da993e31730ff9b91f
4 Schema impact — field nào trong Iglu schema bây giờ chứa hash, không chứa raw 3 field: user_id + user_name + phone_number trong entity user_context + field user_id trong base event data

Sample SQL cho data team (BigQuery / Snowflake / Postgres)

-- Join event với DB customer để biết hash này là user nào
-- (chạy ở phía data warehouse với salt được cấp riêng)
WITH hashed_customers AS (
  SELECT
    customer_id,
    phone_number,
    sha256('fe0430c4b75ff6ba73552117691ca0aba862a1633e5db6b0c1c8fa6b35203886' || phone_number) AS phone_hash
  FROM dim_customer
)
SELECT e.event_name, e.session_id, c.customer_id, c.phone_number
FROM fact_events e
LEFT JOIN hashed_customers c ON e.user_id = c.phone_hash
WHERE e.event_name = 'camera_stream_started';

8. Offline queue + retry

Khi user offline (airplane mode, mạng yếu), SDK không drop event. Pipeline:

[Tap event] ↓ SDK persist vào SQLite local ↓ HTTP queue thử send → fail vì offline ↓ retry timer (exp backoff) [User mở lại mạng] ↓ SDK auto-drain queue → ingest endpoint + Snowplow collector ↓ Event vẫn giữ session_id + timestamp ORIGINAL (lúc tap) ↓ Backend thấy event bay muộn nhưng attribute đúng session

Cộng thêm kill detection (từ tag 0.3.11): nếu user force-kill app, lần cold start kế tiếp tự fire 1 session_ended với reason killed_recovered cho session đã chết — backend sẽ thấy session đóng đúng thay vì bỏ ngỏ.

API kiểm tra queue

UniTrack.pendingEventCounts()Map<event_name, count> — số event đang chờ flush
UniTrack.flush()Force flush ngay (vd trước khi background)

10. Troubleshoot

Q1. Console không thấy log [FSDK] config loaded

iOS: Verify file JSON đã add vào Xcode target FPTLife → Build Phases → Copy Bundle Resources.
Test: grep trackingConfig FPTLife.xcodeproj/project.pbxproj phải thấy 4 dòng.

Android: Verify file nằm ở app/src/main/assets/tracking_config.json (chữ thường + underscore). KHÔNG đặt ở res/raw.

Q2. Event không bay lên BE mà console thấy track

  • Check network — SDK queue offline OK, sẽ flush sau khi có mạng
  • Check UniTrack.pendingEventCounts() — nếu > 0 → đang queue, retry
  • Check ingest endpoint — cfg.endpoint phải đúng URL BE
  • Console log HTTP POST ... → 4xx/5xx → check server side

Q3. Snowplow side thiếu event nhưng ingest queue có

  • Schema chưa register trên Iglu registry → Snowplow tracker drop event
  • Helper gọi snowplow?.trackingClickEvent hay UniTrack.track trực tiếp? Cách 2 bypass Snowplow (xem 6.2)
  • cfg.snowplow.enabled phải true trong JSON

Q4. user_id null trong session

  • FPT Life iOS từ tag 0.3.43 đã wire UniTrack.identify() trong restoreCachedIdentity() → call ở bootstrap, user_id restore ngay sau load JSON
  • Verify UserDefaults / SharedPreferences có FSDKTracking.cachedUsername
  • Sau login phải gọi FSDKTracking.identify(...) để persist + fire UniTrack.identify

Q5. W3C trace_id không inject vào HTTP outbound

  • Check cfg.tracing.enabled = true trong JSON
  • Check cfg.tracing.allowlist_hosts chứa host đang gọi
  • App nếu dùng Alamofire/OkHttp custom session phải đảm bảo dùng URLSessionConfiguration.default hoặc init AFTER UniTrack.initialize
  • iOS console: tìm log [W3C] inject host=... hoặc [W3C] skip host=...

Q6. Build fail "duplicate class UniTrack" trên Android

Xảy ra khi host link CẢ Flutter plugin unitrack lẫn native unitrack-sdk:unitrack. Fix: set unitrack.skipVendor=true trong gradle.properties → plugin sẽ skip vendor binary.

Q7. Trace_id native + Flutter HTTP không link

Default 2 layer mint trace_id riêng. Để bridge: dùng UniTrackHttpClient wrap Dart HTTP (từ unitrack pub.dev 1.2.x). Native swizzler URLProtocol tự inject cho HTTP qua URLSession.
