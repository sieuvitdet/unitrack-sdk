Portal Config · Realtime vs Reinit Field nào anh save trên Portal là app pickup ngay — field nào phải kill + restart app

Áp dụng cho: FPT Life iOS (UniTrack 0.3.36+), Android Native, MobiX Flutter có wire foreground re-fetch.
Cơ chế hot reload: SSE stream (/config/stream) hoặc onAppForeground throttle 5'. Khi save Portal → SDK fetch lại → FSDKTracking.start(remote:) chạy lại → re-wire providers.
Ngày cập nhật: 24/06/2026

Tóm tắt nhanh

✅ REALTIME (16 field)

Anh save Portal → SDK pickup trong <1s (SSE) hoặc <5 phút (foreground throttle).

Demo được: đổi Snowplow appId, bật/tắt provider, đổi event_names, đổi tracing hosts.

⚠️ REINIT (10 field)

Anh save Portal nhưng SDK KHÔNG đổi cho đến khi anh kill + cold start app.

Lý do: C++ core init một lần, swizzler đã install vào URLSession/UIControl runtime — không gỡ realtime được.

Demo script cho khách

Demo 1: Đổi Snowplow appId realtime

  1. Mở Portal pid=8 → Config tab → Snowplow Details
  2. Đổi appId: 505 → 999
  3. Save
  4. Quay sang Xcode Console — chờ SSE log: config_changed version=N+1
  5. Tap bất kỳ button trong app → fire event
  6. Mở Snowplow collector hoặc Portal Sessions tab — event mới có appId=999

Thời gian end-to-end: 1-2 giây (SSE push) hoặc <5 phút (foreground throttle).

Demo 2: Bật / tắt Firebase realtime

  1. Portal → Providers → bỏ tick Firebase checkbox
  2. Save
  3. Tap button → Firebase DebugView dừng nhận event (UniTrack adapter no-op)
  4. Tick lại Firebase → save → event tiếp theo lên Firebase trở lại

Demo 3 — Reinit: Đổi batchSize

  1. Portal → SDK Behavior → batchSize 10 → 1 (gửi event ngay)
  2. Save → fire event → vẫn batch 10 (offline queue C++ core không re-read)
  3. Force kill app (swipe up) + cold start lại
  4. Fire event → giờ flush ngay từng event (batch 1)

⚠️ Đây là điểm phải giải thích cho khách: SDK đã start xong, không thể re-read C++ runtime config.

Tại sao 2 nhóm field hành xử khác nhau?

Hot-reloadable (nhóm 1)

Các field này được đọc tại fire time hoặc qua provider rebuild:

  • Provider rebuild: start(remote:) luôn gọi removeAllProviders() trước khi addProvider(SnowplowProvider(newCfg)). Tất cả Snowplow config sống trong provider instance — instance mới mang value mới.
  • Static swap: screenStartEvent / screenEndEvent / screenLoadEvent là static var trong UniTrack. applyHotConfig() đổi static → mọi lần swizzler fire đọc giá trị mới.
  • Fire-time read: firebase.enabled, tracing.* đọc từ UniTrackRemoteConfig.latest mỗi event — chỉ cần update latest là xong.

Cold-config (nhóm 2)

Các field này wired vào C++ core khi ut_init chạy hoặc swizzler khi install method:

  • C++ core idempotent: UniTrack.initialize() có guard isInitialized (line 768). Lần gọi thứ 2 trở đi là no-op — ut_init không chạy lại, không re-read JSON config.
  • Method swizzling: trackNetwork=true → URLProtocol.register được gọi 1 lần ở init. URLSession.shared đã bind class chain — Apple không có API gỡ runtime.
  • Tương tự cho tap/screen: ControlSwizzler.install(), ViewControllerSwizzler.install() hoán đổi IMP của class — gỡ runtime sẽ phá apps khác cùng class.

Workaround cho nhóm REINIT (tương lai)

Nếu khách cần realtime cả nhóm 2, em có thể bump SDK thêm 2 API:

API mớiTác dụng
ut_reconfigure(ctx, newConfigJson)C++ core re-read batchSize / flushIntervalMs / logLevel / sessionTimeoutMs runtime
UniTrack.setAutoCaptureFlags(...)Toggle Swift swizzler: tap = guard check, network = bỏ chèn vào props builder, KHÔNG gỡ swizzle nhưng skip emit

Effort: ~1-2 giờ wire 2 API. Khi nào khách yêu cầu thì em làm.

Verify cách realtime hoạt động ở app của anh

Bước check Xcode Console: sau cold start, anh thấy log:

UniTrackConfigStream: connecting https://mobix.asia/event-tracking-mobile/config/stream
UniTrackConfigStream: connected

→ SSE listener đã hoạt động. Anh save Portal sẽ thấy log:

UniTrackConfigStream: event=config_changed data={"version":N}
[FSDK] start(remote:) — v(N) endpoint=... snowplow.appId=...

Nếu KHÔNG thấy "connecting" → SSE chưa wire (hoặc verboseLogging=false ở release). Nếu thấy "connecting" nhưng không "connected" → network/firewall chặn SSE.
