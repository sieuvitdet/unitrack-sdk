Screen View Duplicate — Root Cause & Fix

UniTrack SDK auto-capture screen_view / screen_viewed bị bắn nhiều lần khi ViewController rerender

Ngày: 2026-08-11 App impacted: FPT Life (FLI) SDK version: iOS 0.3.60 / Android 0.3.56 Severity: High

1. Tóm tắt

Bug: Event screen_viewed (fan-out từ UniTrack.setScreen) fire 2 lần cho cùng 1 màn hình mỗi khi viewDidAppear chạy lại trên cùng 1 UIViewController instance — dismiss modal/sheet/alert, resume từ background, scene reactivation. Dedup hiện tại chỉ chặn payload screen_exited nhưng KHÔNG chặn screen_viewed khi previous == name.

Impact
Inflated page-view counts, sai session engagement, sai funnel dropoff, sai unique-screen count trong Snowplow.
Trigger phổ biến ở FLI
Live camera view (present modal calling, permission sheet, error alert → dismiss về Live), bg→fg trên bất kỳ screen nào.
Files affected
platforms/ios/Sources/UniTrack/UniTrack.swift:709-800
platforms/android/unitrack/src/main/java/com/unitrack/sdk/UniTrack.kt:787-843
Fix
1 dòng guard trước dispatchToProviders(screenStartEventName). Áp dụng 2 platforms + SPM mirror.

6. Root cause

File: platforms/ios/Sources/UniTrack/UniTrack.swift:790-799
File: platforms/android/unitrack/src/main/java/com/unitrack/sdk/UniTrack.kt:836-843

dispatchToProviders(screenStartEventName, startPayload) chạy vô điều kiện ở cuối setScreen, không check trường hợp lastScreen == name (cùng screen gọi lại). Dedup hiện chỉ áp vào screen_exited fan-out — bất đối xứng.

7. Fix đề xuất — 1 dòng guard

iOS · UniTrack.swift

shared.lastScreenLock.lock()
previous = shared.lastScreen
let isSameName = (previous == name)
if isSameName { previous = nil }
if let prev = previous, !prev.isEmpty, let lastAt = shared.lastScreenAt {
    dwellMs = Int(now.timeIntervalSince(lastAt) * 1000.0)
}
shared.lastScreen   = name
shared.lastScreenAt = now
shared.lastScreenLock.unlock()

...

// screen_exited fan-out (giữ nguyên)
if shared.screenLifecycleEnabled, let prev = previous, !prev.isEmpty {
    ...
    dispatchToProviders(shared.screenEndEventName, endPayload)
    AppLifecycleObserver.rollScreenCounters()
}

// screen_viewed fan-out — NEW guard
var startPayload: [String: Any] = ["screen": name, "screen_name": name]
if shared.screenLifecycleEnabled, let prev = previous, !prev.isEmpty {
    startPayload["from"] = prev
    startPayload["from_screen"] = prev
    startPayload["previous_screen_name"] = prev
}
if !isSameName {
    dispatchToProviders(shared.screenStartEventName, startPayload)
}

Android · UniTrack.kt — parity

val previousBefore = shared.lastScreen
val isSameName = (previousBefore == name)
...
if (!isSameName) {
    dispatchToProviders(shared.screenStartEventName, startPayload)

8. Behavior sau fix

Kịch bảnBeforeAfter
Dismiss modal về same VC 2× screen_viewed 1× screen_viewed
Bg→Fg trên cùng screen 2-3× screen_viewed 1× screen_viewed (nguồn Lifecycle giữ, swizzler race bị dedup)
Navigate sang screen mới 1× screen_exited + 1× screen_viewed 1× screen_exited + 1× screen_viewed (không đổi)
Cold start 1× screen_viewed 1× screen_viewed (không đổi — previous=nil, isSameName=false)
Regression risk: Thấp. Guard chỉ chặn fire khi lastScreen == name — đây là 100% trường hợp "gọi lại cho cùng screen", không có case hợp lệ nào cần bắn screen_viewed lần 2 cho cùng screen trong cùng foreground window.
